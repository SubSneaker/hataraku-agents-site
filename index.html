Hataraku Agents

Your agents at work

Every AI coding agent on your machine shows up as a pixel-art worker in an isometric office. You can see who is working, who finished and who is waiting for you. Click anyone to jump into their session.

Floor 01

One worker per session

When a session starts, a worker comes up the elevator, badges in at reception and sits down at a desk. When it goes quiet they pack up and leave. Looks and first names come from the session id, so a resumed session comes back as the same person.

  • Working

    Orange outline and a spinning gear. A turn is in progress.

  • Idle

    Blue outline and zz. Checked in with nothing new for you.

  • Finished

    Green check. Done and not looked at yet, so an envelope lands on your desk.

  • Need approval

    Blocked

    Red outline. Waiting on a permission, a question or an error. Or it looks stuck.

The badge shape carries the meaning too, so colour is never the only signal.

A room per project

Each git repo gets a department room. Everything in it means something.

  1. Nameplate. Project name, current branch and a chip with the open PR count.
  2. CI monitor. Steady green check when passing, a spinner while running, a blinking warning triangle when failing.
  3. PR ticket rail. One ticket per open PR. Grey is draft, purple is open, a green stamp is approved and a red stamp is changes requested.
  4. Whiteboard. The lead agent's todo or plan progress.
  5. A raised hand. This worker needs you. The bubble stays up until you answer.

Loose papers on the floor are uncommitted changes. Confetti means a PR just merged. Subagents sit next to their lead, and worktrees get their own desk with a branch sign.

The big desk is yours

You are the Boss. Finished work, approvals, questions and new PRs pile up as envelopes on the desk in the corner office. Click the desk for the inbox, then click an envelope to jump to the worker.

  • Result. A lead agent finished a turn.
  • Approval. An agent needs permission.
  • Question. An agent asked you something.
  • Pull request. An agent opened a PR.

What you can do from the office

Every app is read locally and read-only. Clicking any worker gives you Open session, which takes you to that session in its own app. Some apps let you do more without leaving the office.

Actions available from the office for each app
App Message Approve or deny Stop
T3 CodeConnect T3 Code once in Settings. Yes Yes The running turn
Claude Code Idle sessions With the Claude Code hook A session running in a terminal
Codex Idle threads while the Codex app is closed With the Codex hook No
Hermes Idle chats while Hermes isn't running No A session running in the terminal
Cursor Idle cursor-agent chats while Cursor is closed Review and deny agent commands with the Cursor hook No
Windsurf, AntigravityOpen the workspace. No No No

Connections and hooks are set up in Settings > Connections with one click and removed the same way. A message to an idle session runs as a new turn in the background, and the worker gets back to work in the office. Windsurf support is covered by test fixtures only and hasn't been tried on a real install yet.

Build mode

Rearrange the office

Press B to move furniture, add furnished rooms, restyle floors and make the floor bigger. Your agents keep working while you build. Anyone whose desk moves walks over to the new one.

Every edit is checked first. If it would make the office implausible, it's refused and the panel tells you why:

  • Ping-pong table overlaps the office chair
  • Couch needs free space in front
  • Nobody can get to the office chair
  • A desk chair is cut off from the elevator

Room templates: Department, Cubicles, Lounge, Kitchen, Play room and Meeting room. Undo keeps 100 steps.

Play room

A small office for the corner of your screen

Pet mode frames the Boss office and the two busiest rooms in a small transparent page. A strip at the top counts finished, idle, working and blocked workers. Click a worker for a card with Open session.

Open /?mode=pet on your running office, or try the demo version.

Server room

It stays on your machine

The office only reads what your agent apps already keep on disk, and it never phones home.

Local only
The daemon binds to 127.0.0.1. Every request needs the access token in ~/.hataraku-agents/token, which only your user account can read.
Read-only
It never writes to any agent's files. SQLite databases are opened read-only, and files like .env, auth.json and OAuth credentials are skipped.
Redacted
API keys, GitHub tokens, JWTs, private keys and auth headers are masked before anything leaves the daemon.
No LLM calls
Nothing is sent to any model or service. The only network calls are gh requests for PR and CI state, and only if gh is installed and signed in.
One folder
The daemon writes only to ~/.hataraku-agents/: its config, state, layout and event log.

Reception

Run it

From a checkout of the repo. You need Node.js 24 or newer (23.6 is the minimum) on macOS, Linux or Windows.

An authenticated GitHub CLI adds PR and CI signals. Everything else works without it.

Start the office 
npm install
npm run dev

The terminal prints a link like http://localhost:5317/#token=… and opens it. The token connects that tab to the daemon.

Demo without any agents 
npm run dev:web

Then open http://localhost:5317/?demo=1. Nothing on your machine is read.

Daily use 
npm run build && npm start

The daemon serves everything itself and opens http://127.0.0.1:4317/#token=….
